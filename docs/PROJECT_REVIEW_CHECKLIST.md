# Project Review Checklist

Этот файл фиксирует состояние после правок по `PROJECT_REVIEW.md`.

## Статус

- [x] Инъекция подтверждается не по факту создания remote thread, а по `LoadLibraryW` exit code и пост-проверке наличия модуля в процессе.
- [x] После инъекции есть строгая проверка, что DLL действительно присутствует в целевом процессе.
- [x] GUI больше не сохраняет состояние инъекции слишком рано.
- [x] GUI больше не показывает optimistic success-сообщения без подтвержденного состояния.
- [x] GUI перестал вызывать Go-экспорты через `CreateRemoteThread`.
- [x] File-based fallback теперь подтверждает `command accepted` и `script executed` через ack-файлы.
- [x] Критическая логика DLL вынесена в явный idempotent startup (`ensureRuntimeStarted`), а `init()` оставлен только как минимальный bootstrap.
- [x] У DLL есть внешний ready-сигнал (`ready.json`).
- [x] У DLL есть файловый runtime log с подтвержденными событиями (`runtime.log`).
- [x] Пути к DLL передаются через `LoadLibraryW` и wide-string буфер.
- [x] Lua runtime защищен явной синхронизацией.
- [x] File-based IPC переведен на уникальные имена команд, атомарную запись и подтверждение обработки.
- [x] Битые command-файлы теперь помечаются как invalid и не зацикливают watcher.
- [x] CLI и Python-инжектор теперь диагностируют состояние загрузки строже.

## Приоритет 1

- [x] Инъекция больше не считается успешной только по ненулевому результату попытки создать поток.
- [x] Состояния разделены на `module loaded`, `runtime ready`, `command accepted`, `script executed`.
- [x] Optimistic logging убран из инжекторов и GUI.
- [x] Прямой вызов Go-экспортов как thread entrypoint убран из GUI-потока выполнения.

## Приоритет 2

- [x] Добавлена обязательная пост-проверка присутствия модуля в процессе.
- [x] `gInjectedPid` и `gInjectedDllPath` сохраняются только после подтвержденного состояния.
- [x] Зависимость от `init()` снижена: реальная инициализация стала явной и повторно-безопасной.
- [x] Добавлен явный handshake готовности DLL после инициализации.
- [x] Загрузка DLL приведена к Unicode-safe пути.

## Приоритет 3

- [x] File IPC сделан устойчивее: уникальные имена, атомарная запись, подтверждение обработки.
- [x] Идентификаторы команд теперь достаточно уникальны и не зависят только от `GetTickCount64()`.
- [x] Обработка очереди и наблюдение за командами разнесены по отдельным циклам.
- [x] Lua runtime защищен единым сериализованным доступом.
- [x] Логирование приведено к подтвержденным состояниям, а не к факту попытки.
